# Station Designer Unity port (`unity/`)

The Unity port ships the station-building sandbox as a Unity 6 URP runtime behind the shared React 19 UI shell — as a packed WebGL player, a live in-Editor Play Mode session, and a `StandaloneWindows64` `.exe` build — while keeping `GAME-SPEC.md` and the TypeScript game (`game/src/`) as the behavioral oracle and asset generator.

- For Three.js / source GLB conversion, CLI recipes, `prove-model.ps1`, `prove-bench.ps1`, `glTFast` basis/material rules, station finishes and catalogue generation, read [the Unity asset conversion sub-guide](references/assets.md).
- For game rules, module specifications and passenger rigs, consult `metro-game`, `metro-game-test` and `metro-model`.
- For reproducible performance investigations, use [the shared performance reference](../metro-repo/references/performance.md) — never create a parallel Unity performance document; functional/smoke durations belong in test and run reports.
- Local working plans and RCA notes under `unity/plan/` are gitignored (untracked in Git, kept locally when present); treat C#/TS source and `unity/tests/` as the committed source of truth and never link to `unity/plan/` from tracked docs.

## Toolchain and execution loops

Shortcut parity lives in the shared AppShell and the Unity bridge. Ctrl+S uses
the toolbar export and downloads the committed revision. Fetch the save from
the host if the cached document is older. Home sends `camera.frame` and retains
the current orbit and zoom. Route carried-piece R, Tab, Enter and Escape to the
host edit session. Keep rectangular-light position in the preview, clearance
and persisted record. A keyboard delete targets one selected block. Windows
forwarding uses the system key-repeat settings and releases keys on focus loss.
Use the WebGL verifier's `--only shortcut-save,shortcut-move` cases on the small
fixture. The save check imports through the production file input because Chrome
owns Ctrl+L. The move check dismisses the tutorial before testing Escape.

Pinned in `unity/ProjectSettings/ProjectVersion.txt`, `unity/Packages/manifest.json` and `unity/scripts/node-version.txt`:

### Live Editor, in-canvas desktop/Editor React UI, isolated batch & gitignored build inputs

- **Asset `.meta` & `ProjectSettings` rules:** `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset` is rewritten by WebGL shader stripping and is allowlisted as `MUTABLE_BUILD_INPUTS` in `metro-unity.ps1` and `start-unity.mjs`; all other project and fixture inputs must match pre/post SHA-256 provenance. `ProjectSettings/TagManager.asset` defines User Layer 8 = `ExplodedPresentation` for `StationExplodedView`. - **Build targets, the Pipeline package and the parity matrix (plan 27 pitfalls, all measured):**
  - **Windows standalone player:** `Metro.Editor.BuildWindows.Run` builds it, mirroring `BuildWeb`
    (fresh output dir beneath `.preview/unity`, `<dir>.report.json`, hard failure when
    `MetroStation.exe` is missing; the React overlay is staged by `StationEditorReactOverlay`'s
    `StandaloneWindows64` postprocessor). Invoke with the **Editor binary**, not the `unity` CLI
    (that CLI is a harness wrapper and rejects `-batchmode`):
    `& "C:/Program Files/Unity/Hub/Editor/6000.6.8f1/Editor/Unity.exe" -batchmode -nographics
    -projectPath unity -logFile .preview/unity/windows-build.log -quit -buildTarget
    StandaloneWindows64 -executeMethod Metro.Editor.BuildWindows.Run -metroOut <dir>
    -metroConfiguration Release`. Stop the open Editor and delete `unity/Temp/UnityLockfile` first.
  - **Build-target provenance trap:** a `npm run build:unity` fails its own check ("Project inputs …
    changed during the build") when the Editor's active target is not WebGL, because the build
    switches target *inside* the run and rewrites `ProjectSettings` after the pre-build snapshot.
    After any standalone build, commit the switch back with a no-op
    `-batchmode -nographics -projectPath unity -quit -buildTarget WebGL` run and restore any
    `ProjectSettings/UnityConnectSettings.asset` diff before rebuilding.
  - **Never delete `Library/PackageCache/com.unity.pipeline@…`.** That package is installed by the
    `unity` CLI, not fetched from the registry; deleting it makes every Editor compile fail with
    `CS0246: CliArgAttribute/CliArg could not be found` and the Editor never starts its Pipeline
    server (`STATUS_PIPELINE_LOAD_PENDING`). Repair: `unity pipeline install --project-path unity
    --force`, then let the Editor finish importing. Diagnose with `unity status` first.
  - **`StationEditResolverTests` is live-Editor-only.** It passes via `metro-editor.ps1 test` (5/5)
    but makes an isolated `metro-unity.ps1 test` batch process **exit 2** every time; run that
    fixture against the open Editor, and the other port fixtures in either mode.
  - **Probe budget:** `StationPointerRouter.ProbeBudgetFor` bounds the `edit.probe` walk by document
    size (48 candidates at 20k+ cells, 96 at 8k+, 192 otherwise). It is a main-thread guard, not a
    fix for a heavy station: Tanwei still times out in `Input.dispatchMouseEvent` at 300 s with the
    budget at 48, so a heavy station needs a capable harness (or a smaller demo), not a bigger
    timeout.
  - **Mojibake repair is comment-scoped only.** The CP1252→UTF-8 decoder is safe when it can touch
    only lines whose trimmed start is `//`, `*` or `/*`; an unrestricted code-point scanner decoded
    across comment/code boundaries and broke C# syntax in three files (restored from HEAD). After
    any such pass, run `check-unity-compile.ps1` and the owning fixture, and worth keeping in mind:
    the fallback station name `未命名车站` lives in three string literals (`StationGameHost` ×2,
    `StationLoadCoordinator`), so audit string literals, not only comments.
- **Gitignored Unity paths (`.gitignore`):** `unity/` is tracked directly, while `/unity/plan/`, Editor/IDE state (`Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/`, `.utmp/`, `*.csproj` except `!tools/unity-editor-ui/MetroEditorWebView.csproj`, `*.slnx`), build folders (`Build/`, `Builds/`, except `!/unity/Assets/StationDesigner/Runtime/Build/`), and build/local-profile outputs (`Assets/StationDesigner/Demos/`, `Generated/{RuntimeCatalogue,TrainCatalogue}.asset`, `Scenes/StationGameLocalWeb*.unity`, `Generated/Passengers/passenger-catalogue*.asset`) are gitignored. `start-unity.mjs` (`npm start unity` / `npm run build:unity`) regenerates `Demos/` and the runtime catalogues automatically in `.preview/unity/dev-workspace/project` (and on loopback `127.0.0.1` without an explicit `--scene`, runs `StationLocalProfile.PrepareLocalWebBuild` when `Generated/Passengers/passenger-library.manifest.json` exists locally), `PassengerCatalogueBuilder` (`[InitializeOnLoadMethod]`) auto-builds `passenger-catalogue.asset` on Editor load, and `build-runtime-views.mjs` / `audit-runtime-models.mjs` / `renderer-audit.test.mjs` fall back cleanly when `unity/plan/` is absent. ## Game audio

The Unity shell mounts the shared `gameAudio` and `gameMusic` players through
`game/src/unity-web/unityAudio.ts`. Editor and Windows use the in-canvas
WebView2 host. WebGL uses the browser shell. Both use the same recordings,
volume controls, music pause preference and playback policies as the web game.
Keep `game/public/audio/` as the source for the six edit cues, three ambience
beds, eight music tracks and their attribution. Desktop serves the staged
`public/audio/` at `/audio/`. WebGL packs `UI/audio/` with the UI and sets
`metroUnityAudioBase` to its packaged URL.

`StationCommandRouter` derives cues from existing edit outcomes without another
scene pick. `StationGameHost` sends bounded, camera-relative ambience inputs
from live passengers, trains and rendered road vehicles. The exploded view
uses the positions of its presented passengers and trains. Keep both messages
on the session-scoped `audio` channel outside the station snapshot reducer.
Hover, cancellations, no-ops and parked trains stay silent.

Run `npm run test:unity` for session fencing and packaged audio byte and
MIME checks, and `node --test game/test/audio.test.mjs game/test/music.test.mjs`
for shared playback. In live Editor or WebGL checks, click the game once and
verify music, an accepted edit cue and ambience around active simulation
sources. A browser check with simulated bridge replies verifies shell playback
and asset loading. A live run verifies that the Unity host emits those replies.

## Load-bearing contracts

### 1. Coordinates, handedness & flat-box winding (`StationCoordinates.cs`, `GeometryKit.cs`)

- Saved documents, `Metro.Sim` and `Metro.Build` stay in source axes: plan `(x, y)` in metres, elevation `z` in metres (`STOREY_HEIGHT = 5`, station `levelBase`; integer `Facts.Z` drives storey indexing while `Facts.ExactZ` preserves fractional height for wall-mounted plaques/displays).
- `Metro.View.StationCoordinates` is the **sole** conversion point (`ModulePlacement` delegates to it): document `(x, y, z)` maps to Unity world `(x, z, y)`. Do not add implicit `+0.5` or `+1` in raw `Point` conversions; use `CellCenter` and `FloorTop` explicitly.
- Saved quarter-turns map to **`-90° * rot` Unity yaw** (`ModuleRotation(rot)`).
- Family builders receive a parent `Transform` already placed in world space and build in local space — never swap axes a second time. Note that opening GLBs wrap Z-up content in a `-90°`-about-X node, so swing door hinges rotate around `OpeningAxis.Z` (`SwingUp`) rather than local Y, cabinet measurements on `glTFast`-mirrored prefabs must transform bounds into holder space (`TryMeasureGateJambInHolder`), corner-pivoted prefabs whose bay offset is already baked relative to cell `(0, 0)` (`court-{pickleball,badminton,divider}`) skip `ModulePlacement.RunCentre` and register measured `TryDocumentBounds`, and `MeshTopology.Lines` submeshes (`court-net-mesh`) must be guarded before calling `GetTriangles(...)` in `StationExplodedTrayBuilder` and `StationPlacementPreview`.
- Procedural box parts (`BoothModuleViews`, `VerticalModuleViews`, `PsdReturnTrim`, etc.) must emit 24-vertex outward-wound quads with per-face flat normals via `GeometryKit.BoxFaces` — never 8-vertex shared-corner perimeter tables, which produce inverted bowtie triangles and smoothed sheet-metal normals (`MeshWindingTests`). Procedural ramp/stair parts in `VerticalModuleViews.PartMesh` likewise extrude closed stadium/parallelogram outlines (`ExtrudePolygonDoc`) and smooth torus/hemisphere shells (`TorusArcDoc`, `HemisphereDoc`) in document axes before converting once via `Doc(...)`, and `StationCellMesher.MeshSession.FaceRecord` keys faces by a lossless 128-bit `FaceRecordKey` so two's-complement odd `±y, ±z` cells never collide.
- Camera snapshots convert Unity's rendered `right`, `up` and `back = -forward` back into document axes so React's `ViewCube` dots its six face normals directly without quaternion handedness ambiguity.

### Passenger routing and lift verification

- Use `game/src/sim/agents.ts` and `station.ts` as the behavior reference. Street arrivals and train alighters both need the 3% step-free and 8% luggage mix. Unity samples alighter needs by passenger ID so existing demand draws stay reproducible. Step-free searches skip stairs and escalators. Lift edges carry a 40-second cycle estimate, live queue wait at 15 riders per cycle, landing congestion, and the 0/30/300-second mobility penalty.
- `StationServiceRuntime.BuildServiceFacts` registers doors with walkable landings as lift edges in `StationRoutePlanner`. Live A* searches compare them with stairs and escalators in the same search and can chain shafts. Preserve lift edge identity when splitting the result into walking segments. Gate and ride queue replans search to the trip's destination so they can change a later lift choice.
- **Vertical circulation parity & animation contracts:**
  - **Multi-flight stair avoidance & live queues:** `StationSessionProjection.ModuleFact` projects `StairFlights` (`StationRunGeometry.StairFlights(m).Count`) and `RideWidth` (`cfg.width`) onto `StationModuleFact`, propagated identically by `StationWalkGraphBuilder` and `StationWalkGraphWorkspace` onto `StationServerFact`. `StationRoutePlanner` (`Astar` and `RouteCost`) charges `StairAvoidSeconds * StairFlights` (matching Web's per-flight `KIND_STAIR` edges: `64 s` for 2-flight switchbacks/turns, `128 s` for 4-flight runs), and `StationServiceRuntime.SyncServerQueue` keeps `graph.Servers[i].QueueCount` live on every queue mutation.
  - **Ride queues, balustrade detours & escalator geometry:** `StepRideQueue` spreads waiting stair/escalator riders behind front slots with rank-scaled standoff and `DensityDerate`, gates `StepRides` admission on `RideApproachRadius = 0.95 m`, and detours queued passengers around separating balustrade tips via `CanStepTo` + bounded-BFS `NextWalkStepToward`. Both walk-graph builders share `EscalatorCenterShift` (wrapping all authored lanes in `RampWalls`), `EscalatorBlockedLowerCells` (blocking `< 2.2 m` headroom truss cells), and `LiftBlockedCells` (blocking every served lift stop's shaft interior). `RampWalkingLine` omits entry/exit doglegs on escalators/walkways, `StationRidePath.Point` applies lateral `column` offsets uniformly across endpoints, and `PassengerSupportResolver` reports both endpoint storey bands for `Riding` ramp actors so riders never pop in mid-escalator.
  - **Elevator walk-in/walk-out animation:** `StationServiceRuntime` steps lift riders through `LiftPhase` `0` (walk in through `LiftDoorThreshold` to rotation-aware `LiftCabinSlot` while doors stay open via `IsLiftExchanging`), `1` (ride inside cabin facing out the door), and `2` (walk out onto `LiftDestNode` before resuming `Walking`). `PassengerCrowdRenderer.Adjacent` interpolates across all lift state transitions (`Queuing <-> Walking <-> Riding`, `|dz| < 3.0` for `2.25 m/s` eased peak travel) and keeps `WalkWeight = 1` immediately when starting to walk from rest.

including at stair openings. Independently hideable masonry roof geometry is
the exposed cap of a backed deck at or above grade with a full 2 × 2 footprint.
Keep its sides and underside in their normal roles.
