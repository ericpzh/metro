# Station Designer Unity port (`unity/`)

The Unity port ships the station-building sandbox as a Unity 6 URP runtime behind the shared React 19 UI shell — both as a packed WebGL player and as a live in-Editor Play Mode session — while keeping `GAME-SPEC.md` and the TypeScript game (`game/src/`) as the behavioral oracle and asset generator.

- For Three.js / source GLB conversion, CLI recipes, `prove-model.ps1`, `prove-bench.ps1`, `glTFast` basis/material rules, station finishes and catalogue generation, read [the Unity asset conversion sub-guide](references/assets.md).
- For game rules, module specifications and passenger rigs, consult `metro-game`, `metro-game-test` and `metro-model`.
- For reproducible performance investigations, use [the shared performance reference](../metro-repo/references/performance.md) — never create a parallel Unity performance document; functional/smoke durations belong in test and run reports.
- Local working plans and packet notes under `unity/plan/` are gitignored (untracked in Git, kept locally when present); treat C#/TS source and `unity/tests/` as the committed source of truth.

### Live Editor, in-Editor React UI, isolated batch & gitignored build inputs

- **`metro-editor.ps1`** talks only to the already-open Editor on `unity/` (`--project-path` scoped, serialized by named mutex `Local\MetroUnityEditorWorkflow`), writing `run.json`, logs and `1280 × 720` screenshots under `.preview/unity/editor/<run-id>/`. `compile` and `test` stop Play Mode first (`EditorSceneManager.NewScene` throws if Play Mode is active); `smoke` leaves Play Mode running unless `-StopAfter` is passed so consecutive smokes take ~8.5 s and can assert identical state SHA-256 fingerprints. If `status` reports `STATUS_NO_INSTANCES`, open `unity/` in Unity `6000.6.8f1` (or run batch checks on a scratch copy).
- **In-Canvas Desktop & Editor Full React UI (`StationDesktopUiPresenter.cs` + `StationEditorReactOverlay.cs` + `tools/unity-editor-ui/`):** On `UNITY_STANDALONE_WIN || UNITY_EDITOR_WIN` (`-batchmode` and `TestRunner` scenes skipped automatically; compiled out on WebGL), `StationDesktopUiPresenter` self-registers a `ScreenSpaceOverlay` `Canvas` + `RawImage` inside Unity's own `Game` viewport / player swapchain and launches `MetroEditorWebView.exe` completely offscreen (zero floating `HWND_TOPMOST` OS windows). The worker hosts `CoreWebView2CompositionController` on a `Windows.UI.Composition` `ContainerVisual`, captures 32-bit `B8G8R8A8_UNORM` frames via `GraphicsCaptureItem.CreateFromVisual` + `Direct3D11CaptureFramePool.CreateFreeThreaded`, unpremultiplies semi-transparent pixels into a lock-free double-buffered `MemoryMappedFile` uploaded via `Texture2D.LoadRawTextureData`, and receives Unity `InputSystem` mouse, wheel and keyboard events over loopback TCP/CDP. In Editor Play Mode, `StationEditorReactOverlay` builds `.preview/unity/editor-ui-host/bin/MetroEditorWebView.exe` + `game/dist-unity-ui` on demand and exposes `Metro/Station Game/*` menus plus `metro editor_ui_{selftest,prepare,wait,capture}`; on `BuildTarget.StandaloneWindows64`, its `IPostprocessBuildWithReport` hook packages the worker and UI bundle into `<Player>_Data/StreamingAssets/MetroUi/`. `StationEditorReactOverlay.SmokeSuppressed` hides the `Canvas` while `StationGameSmoke` captures 3D-only smoke frames. Pinned by `unity/tests/editor-react-overlay.test.mjs`.
- **`metro-unity.ps1`** runs `-batchmode` Unity processes (`doctor`, `bootstrap`, `test`, `build-web`, `pack-web`, `smoke-web`, `import-assets`) and refuses any project containing `Temp/UnityLockfile`. Always point `-ProjectPath` at an isolated scratch copy (`Assets`, `Packages`, `ProjectSettings`, `asset-recipes`) and `-OutputDirectory` at a fresh folder beneath `.preview/unity/`. Never run concurrent Unity batch processes against the same project copy.
- `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset` is rewritten by WebGL shader stripping and is allowlisted as `MUTABLE_BUILD_INPUTS` in `metro-unity.ps1` and `start-unity.mjs`; all other project and fixture inputs must match pre/post SHA-256 provenance. Edit `ProjectSettings/ProjectSettings.asset` only with the Editor closed and **without** a UTF-8 BOM (avoid PowerShell 5.1 `Set-Content -Encoding UTF8`), otherwise Unity rewrites it during batch import and trips the provenance hash guard.
- **Gitignored Unity paths (`.gitignore`):** `unity/` is tracked directly, while `/unity/plan/`, Editor/IDE state (`Library/`, `Temp/`, `Obj/`, `Logs/`, `UserSettings/`, `.utmp/`, `*.csproj` except `!tools/unity-editor-ui/MetroEditorWebView.csproj`, `*.slnx`), build folders (`Build/`, `Builds/`, except `!/unity/Assets/StationDesigner/Runtime/Build/`), and build/local-profile outputs (`Assets/StationDesigner/Demos/`, `Generated/{RuntimeCatalogue,TrainCatalogue}.asset`, `Scenes/StationGameLocal*.unity`, `Generated/Passengers/passenger-catalogue*.asset`) are gitignored. `start-unity.mjs` (`npm start unity` / `npm run build:unity`) regenerates `Demos/` and the runtime catalogues automatically in `.preview/unity/dev-workspace/project`, and `PassengerCatalogueBuilder` (`[InitializeOnLoadMethod]`) auto-builds `passenger-catalogue.asset` on Editor load. On a fresh clone before running EditMode tests directly on `unity/`, run `node tools/unity-parity/export-station-documents.mjs`, `node tools/unity-assets/ensure-meta.mjs`, and `Metro/Station Game/Generate Scene` (`bootstrap -Scene StationGame`).

## Load-bearing contracts

### 1. Coordinates and handedness (`StationCoordinates.cs`)

- Saved documents, `Metro.Sim` and `Metro.Build` stay in source axes: plan `(x, y)` in metres, elevation `z` in metres (`STOREY_HEIGHT = 5`, station `levelBase`).
- `Metro.View.StationCoordinates` is the **sole** conversion point (`ModulePlacement` delegates to it): document `(x, y, z)` maps to Unity world `(x, z, y)`. Do not add implicit `+0.5` or `+1` in raw `Point` conversions; use `CellCenter` and `FloorTop` explicitly.
- Saved quarter-turns map to **`-90° * rot` Unity yaw** (`ModuleRotation(rot)`).
- Family builders receive a parent `Transform` already placed in world space and build in local space — never swap axes a second time. Note that opening GLBs wrap Z-up content in a `-90°`-about-X node, so swing door hinges rotate around `OpeningAxis.Z` (`SwingUp`) rather than local Y.
- Camera snapshots convert Unity's rendered `right`, `up` and `back = -forward` back into document axes so React's `ViewCube` dots its six face normals directly without quaternion handedness ambiguity.

### 2. Self-registration and per-world lifecycle

- Features self-register via `[RuntimeInitializeOnLoadMethod(BeforeSceneLoad)]` (or `AfterSceneLoad` with persistent host-watching bootstrap for `StationViewFeature` and `PassengerServiceFeature`) into `StationRenderers`, `StationCommandHandlers`, `StationFrameSinks`, and `host.RegisterStateContributor(...)`. `StationGameHost` contains no per-family branches.
- **Staging rule:** `StationLoadCoordinator` builds the incoming `StationWorldView` *before* disposing the outgoing world. Every `IStationViewRenderer` singleton **must** key its state per `StationWorldView` and prune only `IsDisposed` worlds in `Release()` (as `OpeningModuleRenderer`, `VerticalModuleRenderer`, `StationCellRenderer`, `StationRoadRenderer`, `TrainConsistRenderer`, `PassengerCrowdRenderer` and `StationSignSignageScope` do) so disposing the outgoing world never wipes the newly staged world's bindings or caches.
- **No silent fallbacks:** Never substitute a generic cube or hide an unsupported record to make a demo pass. Report unresolved modules via `context.ReportUnresolved(...)` and unported sim features via `Unported` diagnostics.

### 3. Bridge v2, WebGL & Editor WebView2 transport, UI bundle stubbing & `#game-loading` (`schemaVersion: 2`)

- C# (`StationGameHost` on GameObject `StationGame`) is the sole owner of the committed document revision, camera, simulation clock and active tool.
- **WebGL `1024 / 4096 MiB` heap ceiling & `.jslib` signature rule:** `unity/ProjectSettings/ProjectSettings.asset` sets `webGLInitialMemorySize: 1024`, `webGLMaximumMemorySize: 4096`, `webGLMemoryGrowthMode: 2` (geometric growth), `webGLThreadsSupport: 0`, and `webWasm2023: 1` (`2048 MiB` OOMs on Zoo with modules; **do not set `webGLMaximumMemorySize > 4096` in Unity `6000.6.8f1`**, as >4 GiB switches Emscripten to memory64/`BigInt` glue that throws `TypeError: Cannot mix BigInt and other types` during `createUnityInstance` before station code runs). Every exported function in `unity/Assets/StationDesigner/Plugins/WebGL/*.jslib` **must** declare `<fn>__sig` matching return + parameter count with `'p'` on pointer arguments passed to `UTF8ToString(...)` (e.g. `StationGameState__sig: 'vp'`).
- `game/vite.unity-ui.config.ts` (`unityHostStubs`) stubs `Viewport.tsx`, `ExplodedView.tsx`, `render/scene.ts`, `CameraSystem.ts` and `data/{tanwei,tianhe}-station.json` at build time, keeping Three.js crowd/map buffers and multi-megabyte JSON saves out of `dist-unity-ui` (~4.05 MiB vs ~84.6 MiB; pinned by `unity-preview-pipeline.test.mjs`).
- `unity-ui-pack.mjs` + `game/src/unity-web/main.tsx` replace Unity's default `#unity-loading-container` slider with the shared `#game-loading` shell (`blueprint` / `site` / `studio` themes, bilingual copy, determinate download progress, localized failure state). `main.tsx` waits two animation frames before synchronous `SendMessage` on `openDemo`/`openSave` so `#game-loading` paints first, and dismisses it on commit or load rejection.
- **JS → C#:** `SendMessage("StationGame", "BrowserCommand", json)` in WebGL (or `window.chrome.webview.postMessage(json)` → loopback TCP → `StationGameHost.BrowserCommand` in `StationDesktopUiPresenter`) with `{ schemaVersion: 2, id, sessionId, expectedRevision?, type, payload }`. Document edits carry `expectedRevision`; session-scoped commands (`camera.*`, `view.*`, `sim.*`, `tool.*`) omit it and never increment `revision`.
- **C# → JS:** `StationGame.jslib` (or `StationDesktopUiPresenter` → `MetroEditorWebView` on desktop/Editor) dispatches `CustomEvent('metro:station-state', { detail })`. `signFaceProvider.ts` intercepts `sign.requestFace` messages first so PNG payloads never enter the state reducer; `stationBridge.ts` (exposed at `window.__metroStationBridge` for browser verification) reduces `commit`, `state`, `ack` and `reject` envelopes with `sessionId` fencing:
  - `commit` carries the normalized v1 `document` string **once** (plus `documentRevision`, `sourceId`, `sourceHash`, `capabilities` and contributor snapshots). `main.tsx` adopts it into Zustand, rewrites `/game/<demo>` URLs via `gamePathFor` only after commit succeeds, and downloads `snapshot.document` directly on Save.
  - `state` publishes coalesced runtime snapshots (`0.1 s` interval when active, never carrying `document`): `clock`, `camera`, `view`, `roads`, `crowd`, `sign`, `queued`, `boarded`, `tool`, `toolGeneration`.
  - `reject` returns stable codes (`revision-mismatch`, `stale-revision`, `unsupported-record`, `parse-failed`, `unknown-tool`, `bad-payload`, `no-session`) and leaves the active station and `revision` untouched.

### 4. Three passenger profiles (public vs local Editor vs local WebGL)

The 440-recipe soft-human library (`Assets/StationDesigner/Generated/Passengers/`, derived from `HumanBody_Alt.fbx`, marked `INTERNAL_REVIEW_ONLY` / `production: BLOCKED`) must never reach a public build (`unity/tests/passenger-profile.test.mjs` scans GUIDs, `EditorBuildSettings.asset`, public build scripts and `--pack` outputs):

1. **Public profile (`Scenes/StationGame.unity`):** Carries no `PassengerCatalogueAnchor`. `PassengerCrowdRenderer` logs `passenger-catalogue-missing` and spawns no 3D passenger actors (no stand-in mesh is substituted in `StationGame`), while `StationCrowdStateContributor` publishes simulation passenger poses with `catalogue: { bound: false, count: 0, rights: "" }` and `recipe: ""` (`Generated/Models/passenger-adult.glb` stays outside `Generated/Passengers/`).
2. **Local Editor profile (`Scenes/StationGameLocal.unity`):** Generated via `Metro.Editor.StationLocalProfile.Generate` / CLI `metro station_local_scene`. Adds a `PassengerCatalogueAnchor` with `catalogue = null` on disk (zero internal GUIDs serialized outside `Generated/Passengers/`) and injects the 440-row `passenger-catalogue.asset` on Play Mode entry via `Editor/LocalPassengerInjection.cs`.
3. **Local WebGL profile (`Scenes/StationGameLocalWeb.unity` + `metro-local-player.ps1`):** Because the 440-row library is ~719 MiB of GLBs, `PassengerCatalogueBuilder.BuildWebCohort(rows = 12)` (`Metro/Passengers/Build Local Web Cohort`) builds `Generated/Passengers/passenger-catalogue-web.asset` (the 5 H1 specimen recipes + evenly spaced rows, 15 unique recipes). `StationLocalProfile.GenerateWeb()` / CLI `metro station_local_web_scene` binds that cohort in `StationGameLocalWeb.unity`, and `./unity/scripts/metro-local-player.ps1` builds via `-ScenePath`, packs (`pack.mjs` matches `/\/StationGame[^/]*\.unity$/`), and serves on `127.0.0.1` only via `static-pack-server.mjs`.
