# `game/src` module map

A file-by-file ownership map of the game. Keep the dependency rule in mind:
`app/ → render/ → sim/`, and `build/ → sim/` (build imports neither render nor
app). `sim/` imports nothing outside itself and never touches the DOM, three or
React.

**Parallel-edit layout.** Most of `game/src` follows the one-unit-per-file rules
of `game/plan.md` (R1–R6). Where a former god-file was split, the original path
is now a **barrel** that re-exports its new folder, so every import (tests
included) still resolves: `sim/world.ts` → `world/`, `build/model.ts` →
`model/`, `render/models.ts` → `models/`, `render/scene.ts` → `scene/`,
`app/store.ts` → `store/`, `app/App.tsx` → `windows/`, `app/LeftRail.tsx` →
`rail/`, `app/SignEditor.tsx` → `windows/sign/`. `app/Viewport.tsx` keeps its
path and delegates pointer work to `tools/`. Read `game/plan.md` before adding a
new window, subwindow, list item, tool, model or scene system.

## `render/` — three.js

| File | Owns |
|---|---|
| `chunkMesher.ts` | `meshChunk`, `CHUNK`/`CORNER_R`/`BEVEL`, rounded-corner voxel geometry grouped into one part per finish. A **半墙** cell (`thin`: packed key → its `CellShape`) meshes as the standard rounded profile squashed to `HALF_WALL_T` and turned into the half it keeps (`buildThinProfile`), so it wears the wall's own profile and its faces keep their own finishes — both sides are paintable — while its inner face, looking across the cell's clear half, is always built. A **三角** cell is not a cross-section at all — the cell is cut in *elevation* — so it leaves the profile path for `pushWedge`: `TRI_FRAME` (the hugged corner, the direction the cut runs into the cell, the ridge axis) writes the wedge's five faces, `pushFace` winds each one against its own geometric normal so the eight `(kind, side)` pieces cannot drift apart, and each face wears the finish of the axis its normal most points along — the rule the 材质 brush reads — with nothing chamfered, because a sawn block is sharp. A block a run cuts (`slope`: packed key → its `SlopeCut`) ends on the run's underside instead: the side walls stop on the plane, the top is a fan of the plain profile on it, and there is no top-rim bevel — a cut stays sharp. Where the plane leaves through the block's floor the cross-section is clipped (`clipProfile`, Sutherland–Hodgman) so the face meets the floor instead of chording back up into the run, and the bottom cap follows the clipped shape. `meshChunk` also takes the caller's own cell list plus `thin`, so a storey band meshes from its chunk-grouped cells instead of walking the whole 16³ volume (`volumeCells`).
