# Subplan 03 · TypeScript gameplay to C#

Read the metro game and test skills first. Use the source at the baseline SHA, the current tests and `GAME-SPEC.md` in that order for behavior. Port one subsystem at a time and make differences reviewable through shared fixture output.

## R1. Create the dependency and fixture boundaries

1. Under `Assets/StationDesigner/Runtime/`, create asmdefs for `Metro.Sim`, `Metro.Build`, `Metro.Persistence`, `Metro.View` and `Metro.App`. Sim and Build set `noEngineReferences`, use plain data, and depend only on base class libraries and the allowed dependency edges. Build references Sim. Persistence references Build and Sim and owns JSON/package dependencies. View reads immutable document data and published sim snapshots. App composes the layers and owns Web interop, audio, input and UI. Editor and test asmdefs are separate. Add a dependency check with the same intent as `game/test/layering.test.mjs`.
2. Create a TS oracle exporter such as `tools/unity-parity/record.mjs`. Run it with the repo Node version and direct TS imports. Create tagged fixtures for isolated unit cases and whole-station replays. Input specifies `schemaVersion`, source SHA, seed, source document, initial clock, warm-up, explicit command order and tick counts. Output includes normalized station, repair counts, graph summary, ordered adjacency on small fixtures, RNG state, event stream, selected agent/queue/train/lift states, history and metrics at specified ticks.
3. Store reviewed small inputs/goldens with the tests. Generate large traces under `.preview/unity/parity/` from the checked-in stations and stable recipe inputs. Use exact equality for keys, discrete state and ordering. Use reviewed field-specific tolerances for numeric outputs computed in floating point and capture first divergence with scenario, tick, ID, field, expected/actual and nearby commands. Keep station names and authored content exact. Canonicalize key ordering only where it is semantically unordered.
4. Start with fixture IDs `empty-station`, `grid-negative-offset`, `legacy-save-repair`, `stair-gate-platform`, `lift-with-queue`, `train-dwell-transfer`, `road-intersection`, `pending-edit-population`, `paused-route-observation`, `seek-vs-restart`, `zoo-1x`, `tanwei-transfer`, `tianhe-64x`. Mirror actual source behavior and use explicit steps rather than wall-clock timing for parity. Run identical fixtures twice per engine. Add failure fixtures with a changed RNG/order to prove the comparer can detect drift.
5. First port only `rng.ts`, `constants.ts`, `clock.ts`, common types and grid math. Use unchecked `uint` arithmetic and unsigned shifts for Mulberry32/Math.imul semantics. Implement UTF-16 code-unit FNV-1a, explicit JavaScript-style floor/truncation/rounding/modulo where used, insertion and tie-break ordering, and float32 rounding where JS writes typed arrays. Keep calculation in `double` where JS used Number. Make JS-to-C# mapping explicit for nullable vs absent, tagged unions, sparse fields and legacy defaults. Use ordinal ID comparisons and invariant wire formats. Test negative coordinates, half-way values, off-day/holiday/date boundary, overflow, and known RNG vectors before implementing World.

## R2. Port the station document and compatible saves

1. Map `sim/types.ts`, `build/model.ts` and `build/model/` to source-coordinate document DTOs, indexes and derived station data. Keep 1 m cells and 5 m storeys, including level base and negative levels. Read the TS coordinate and cell/face key helpers before choosing key structures. Keep stable IDs and insertion order where downstream behavior depends on them. Runtime world/view coordinates are adapted after document validation.
2. Implement `StationSaveReader` and `StationSaveWriter` against `game/src/persistence/save.ts` and `game/test/save.test.mjs`. Use `format: metro-save`, `formatVersion: 1`, `savedAt`, `gameVersion` and static cells/modules/lines. Match v1 fields, defaults, repair counts, date/time/service windows, demand, legacy `cityStyle`, tags and partial older files. Keep user names, labels, signs, lines and bilingual text as authored. Keep dynamic agents, queues, trains and UI prefs out of the save. Use explicit DTO mappings and safe JSON converters, no polymorphic type-name deserialization. Confirm serializer code and converters survive IL2CPP stripping.
3. Parse and repair into a candidate document, validate, then swap it in at one commit. Failed reads leave the running station and its autosave untouched. For known-but-unported module types during the slice, preserve serialized fields and surface a clear unsupported state. For unknown/future records use the shipped reader's observed acceptance/rejection rules and keep the raw original if repair drops content. Treat parity on accepted v1 fields as the cutover rule.
4. For each of Zoo/Tanwei/Tianhe, the authored video save, a small station and malformed/legacy samples run `TS read → C# write → TS read` and `C# read → TS write → C# read`. Compare semantics with `savedAt` controlled, report any repair/warning, and confirm a valid import resets the same runtime state as TS. Demo data JSON and external `.metro.json` may have different shapes. Load demos via the source adapters in `game/src/data/reference-station.ts` or a deterministic generated v1 artifact.
5. The first browser bridge handles UTF-8 import/export, selected locale and autosave with only a small versioned message protocol. On the current origin, read `metro-game.autosave.v1` as a migration source if a Unity save is absent. Keep the original TS bytes and use a separate key such as `metro-unity.autosave.v1` until rollback behavior is approved. For a small save the bridge can use localStorage, but test the large authored and demo saves against browser quota. Use one IndexedDB database with stable app-specific name/key for Unity data if quota or synchronous work is a problem. A new release ID or locale route must resolve the same storage key. Do not rely on Unity's default URL-derived storage namespace for cross-route migration.
6. Prefer a successful legacy autosave on normal startup, and let an explicit demo route outrank all autosaves as today. Use Unity autosave first once it exists. On corruption, unavailable storage or quota failure, show a localized message and leave manual file export available. Save dirty committed revisions on a debounce and while active. On hide/pagehide, flush best-effort without making it the only write path. Test reload after confirmed writes. Expose a Unity-save export before switching to the legacy game, and test importing that file on legacy. Browser data is origin-bound, so use exported fixtures to test migration on preview origins. [Unity browser JavaScript interaction](https://docs.unity3d.com/6000.6/Documentation/Manual/webgl-interactingwithbrowserscripting.html)

## R3. Port graph, navigation and World in playable slices

For each row first port the relevant unit fixtures, then a whole-station oracle replay, then connect the Unity view. Preserve source semantics and optimize on a measured case.

Match paths and costs on representative stairs, ramps and split floors. Use the existing station graph design for crowd behavior. |
| R3.2 | `crowdRouting.ts`, `agents.ts`, `demand.ts`, `activityStops.ts`, `activities.ts`, `gates.ts` | Deterministic spawn/walk/queue/despawn loop with reroute budgets, fare barriers, density derate, queue capacity and stable IDs. Copy the observed one-second logical tick and tick order from `World.tickOnce`. Advance the clock, dispatch trains, spawn agents, step servers, move agents, compact the pool, compute metrics, sample history, then maintain the path cache. Port `sim/protocol.ts` as explicit C# commands/snapshots instead of recreating browser serialization internally. Distinguish `init`, `build`/delta, `population`, `control`, `restart`, `seek` and `selectAgent`. Preserve which controls cause immediate state output and whether a running simulation steps, using tests of current behavior. Include train/lift/route/history snapshots with reset markers. Interpolate per identity between snapshots and keep render phase out of gameplay.

### Web scheduler and feasibility gate

Use one main-thread host with an explicit tick budget and an unscaled accumulator. Speed changes scheduling, and the World always advances in one-second ticks. Carry a bounded, observable backlog policy and report effective rate. Handle pause, hidden-tab and resume explicitly to avoid unbounded catch-up. Capture Unity frame time, individual step time and tick throughput. A frame scheduler spreads work only between completed steps. If one tick or graph edit is too slow, use resumable deterministic work with a stable order and publish atomically at the transaction boundary.

Run an early spike with Tianhe's actual or measured-equivalent graph sizes and synthetic agents at current demo peak. Compare all three demo loads and edits, including one large topology change, long drags and 1×/4×/16×/64×. The spike must exercise graph traversal and queue work as well as rendering. The synthetic workload estimates feasibility, and the final port reruns the gate on actual gameplay. Managed Web threading cannot reproduce the TS worker. Profile allocations, graph/routing and render time before changing architecture. If necessary try pooled buffers, chunking and data layout first. Burst job/native threading is a separate compatible browser and response-header experiment. Require a new review before changing the supported simulation speed or moving gameplay outside Unity. [Unity Web technical limitations](https://docs.unity3d.com/6000.6/Documentation/Manual/webgl-technical-overview.html)

## R4. Port edit transactions and picking

1. Read `game/src/build/`, `game/src/sim/stationEdit.ts`, `populationEdit.ts`, `cosmeticEdit.ts`, `worker.ts` and the store slices. Define commands for place/erase/move/dig/paint/zone, rail/line, road and lift edits. Keep one authoritative document and versioned transactions with undo/redo. Give input the same placement validator for hover and release. Preserve selection keys and author-created values.
2. Resolve one scene pick per pointer event after UI hit exclusion. Store its hit context for preview and gesture operations. Preview reads a committed revision and produces an ephemeral plan. If the revision changes during a drag, revalidate that plan before committing. Render preview independently and release temporary buffers on cancel, tool switch and pointer loss.
3. Commit successful multi-place edits once, keep undo grouped, and use dirty summaries for view and graph. Apply ordered deltas to the latest pending document. Cosmetic edits update data without rebuilding topology when possible. If a structural edit is queued, merge later edits into that pending document and publish a coherent revision. Population-only changes keep the active crowd and also flow into a pending rebuild. Structural rebuilds keep/reproject compatible agents as in TS. Never present a graph revision with stale renderable geometry.
4. Verify hover, drag, cancel, delete, undo/redo, level offsets, open faces, ramps/roofs and mixed topology/cosmetic/population edits. Read `.agents/skills/metro-repo/references/editor-action-matrix.md` and port the comparable cases as black-box editor actions. Confirm route selection is observational and leaves tick, RNG, cache/budget side effects and document revision unchanged as appropriate.

## R5. Attach Unity input, camera and view

1. Generate the input actions and Bootstrap references in code. Map orbit/pan/zoom, scroll, placement, cancel, hotkeys and view cube. Use explicit control state instead of writing to the save on pointer movement. Own the basis transform from [A2](02-assets.md#a2-make-a-deterministic-export-command) in View. Test camera reset, orthographic/perspective, top/front/side, clipping and exploded storeys, pointer visibility and building on negative floors.
2. Port `SceneRenderer` and `scene/systems/` responsibilities into small views. Bind Unity mesh/prefab pools to chunk or model IDs, and publish crowd/vehicle interpolation from immutable snapshots. Bind one quality policy to URP and shader variants. Compare UI interaction with animation and input during worst-case updates. Make debug snapshot export available only in the QA build.
3. Start the first playable smoke from an empty station. Place a floor and gate, undo and redo, open Zoo, run walk → queue → board, pause, download a save, reload and import. Capture C# EditMode/PlayMode results and Web screenshots. Keep a browser check that drives real pointer input, separate from an injected QA command replay.

## R7. Gate parity, speed and release

- Pass deterministic TS/C# fixture comparison and run the C# suites in the Editor and the critical parity fixture set in an IL2CPP Web build. Compare doubles within recorded tolerances and compare discrete outcomes exactly. Reject unintended event reorder, RNG drift or ID churn even if a screenshot looks similar.
- Validate all six demo links, the authored save, locale/IME, imports/exports, autosave, edit/undo, pause/fast-forward, camera and major view states with automated browser evidence. Rerun the key scenarios in a release build with shipping graphics settings. Capture actual Safari/device evidence if they are included in the release scope.
- Propose initial Phase 1 thresholds for the owner to confirm after measuring TS on the chosen minimum-spec hardware. At 1× require p95 frame interval ≤33.3 ms in a representative demo view, p95 pointer-to-preview and commit-to-first-feedback ≤100 ms, and no interaction stall over 200 ms after warm-up. Record graph/edit end-to-end completion separately. Require at least 95% of requested tick throughput at each published speed over a fixed active interval, including 64×, while editing stays responsive. Report relative regressions and variance versus TS. Agree explicit cold start, transfer and memory caps from the measured device and loaded demos before promotion. Static asset size is a separate hard deployment gate.
- Mark each gap-ledger item as passed, owner-approved deferral, or blocking. Record performance findings with reproduction commands, commit, station, hardware and raw output location in the repo performance reference. The migration ends after the same evidence passes on the production route and rollback is verified.
