# Subplan 02 · Three.js assets to Unity

Read the metro game and model skills, `game/src/assets/PASSENGERS.md` and [B3](01-bootstrap.md#b3-approve-and-resolve-dependencies). Build a source-owned exporter with deterministic recipes. Exchange portable geometry in GLB, then import it in the Editor and build Unity prefabs and data. Unity Web consumes Unity's built assets.

Start with the [runnable bench and Type A train examples](skill-drafts/metro-unity-assets/SKILL.md). They exercise static geometry, generated textures, transparent glass and independently articulated door banks in isolated URP projects before the shared catalogue and batch importer are implemented.

## A1. Classify assets and decide what transfers

Create `unity/asset-recipes/catalogue.json` with one row per family and stable ID. Include source paths, owner, license/provenance, classification, variants, anchors, expected dimensions, LOD and validation scene. Pull IDs and parameters from the current catalogue and simulation definitions. Keep any generated subset tied to a source digest.

A cleared rig and motions are needed for the final crowd visual gate.

## A2. Make a deterministic export command

Proposed entry point `tools/unity-assets/export.mjs`. Run from the repo root. Use a local locked dependency workspace and resolve Three.js from the package that owns each generator to avoid a second copy in the same scene. The existing soft-human exporter provides a Node `FileReader` shim and round-trip import example. `tools/browser-harness.mjs` is the fallback for canvas/DOM-backed generators that need the real Web environment. Run a small export page locally with fixed inputs and retrieve bytes from the automation. Use renderer-independent builders for plain meshes. [Three.js GLTFExporter](https://threejs.org/docs/pages/GLTFExporter.html)

```powershell
# Planned after A2 and A3.
node tools/unity-assets/export.mjs --id station.bench.standard --out .preview/unity/assets
node tools/unity-assets/validate.mjs --manifest .preview/unity/assets/manifest.json
./unity/scripts/metro-unity.ps1 import-assets -Manifest .preview/unity/assets/manifest.json
```

1. Define adapters `build(recipe) → { root, clips, anchors, materials }`. Capture original bounds and anchors, normalize only the export clone, and freeze time/random seed. Export from model-local coordinates. For a world-space builder such as `buildModule`, create a canonical module at known origin/facing and remove scene-only transform offsets exactly once. Set meaningful node names and explicitly retain any hidden functional children needed by the import.
2. Pick a single basis contract. Source station/simulation is Z-up with X/Y in the ground plane and one cell per metre. Proposed gameplay bridge maps `(x,y,z) → (x,z,y)` in Unity world. Keep serialized and simulation coordinates in source convention. This swaps handedness. For exported geometry use a proper Z-up to glTF Y-up transform, then account for the importer's own handedness change exactly once with a documented prefab root orientation. Establish the exact basis using an asymmetric axis fixture with `+X`, `+Y`, `+Z` sockets and a front-facing marked triangle. Verify yaw, normals/winding, tangent handedness, local versus world pivots, plus/minus doors and pick cells at four facings. For C# generated meshes apply the reflection and winding swap in the same adapter. Transform headings via basis vectors before deriving Unity rotation.
3. Convert Three materials to a portable contract with a named slot, base color/texture, metallic, roughness, emissive, alpha mode, double-sided flag and normal map. For Three shader mutations and material IDs, emit the Unity shader/material requirement in the manifest. Keep a calibrated neutral lighting scene and compare glass, opaque, unlit decals and linear/sRGB texture semantics separately. Bake supported textures to PNG/JPEG for the first spike. Make unsupported extensions fail validation with a recipe ID.
4. Use `GLTFExporter.parseAsync(root, { binary: true, animations: clips })`. Validate GLB structure, attributes, external URI policy, skin/animation presence and extension allowlist with Khronos' `gltf-validator` Node package. Fail on errors and new warnings outside a reviewed allowlist. Emit one manifest only after all results validate. Use a temporary output directory and atomic promotion, preserve the last good catalogue on failure. [Khronos glTF Validator](https://github.com/KhronosGroup/glTF-Validator)
5. Record per recipe `id`, `schemaVersion`, `sourcePaths`, `sourceSha256`, `exporterVersion`, `recipeSha256`, `glbSha256`, `units`, `bounds`, `basisId`, `anchors`, `materialSlots`, `clips`, `lod`, `triangleCount`, `licenseRecord`. Hash source dependency closure, input asset hashes and locked tool versions. Export twice from identical inputs, compare hashes and reports, and fix unstable ordering or timestamps before introducing cache reuse.

## A3. Import, wrap and validate in Unity

1. Add glTFast through B3. Build `Metro.Editor.ImportAssets.Run` with `AssetDatabase.ImportAsset` and synchronous import for the promoted files. Copy only changed GLBs to stable paths under `Assets/StationDesigner/Generated/Models/`. For intentional removal print stale IDs and require an explicit prune step. Preserve stable meta GUIDs by updating same-path inputs in place. Never hand-edit a generated imported prefab.
2. Find the imported object using Unity's asset APIs. Use separate wrapper prefabs saved via `PrefabUtility.SaveAsPrefabAsset`. Store stable anchors and dynamic part mappings in a catalogue asset, assign materials/LODs explicitly, and use analytic placement bounds from authoritative rules. Static model pieces can use simple visual or pick geometry. Keep runtime traversal and build collision independent of a model's mesh collider.
3. Verify with EditMode tests for named nodes, scaled local bounds, material slots, expected triangle/submesh counts, clip durations and channels, bone weights/root, generated reference validity and import idempotency. Open a generated review scene in a desktop capture player and Web player. Compare silhouette, yaw, pivots, transparent sort, leg/door motion and appearance at both near and far distance to fixed source views. Start with a one-metre cube tolerance of 1 mm and document per-asset visual tolerances for curved/skinned geometry.
4. Keep approved immutable source assets and the metadata required for stable references in version control where practical. Keep reproducible bulky intermediates under `.preview/unity/` or in build artifacts. If a generated GLB is omitted from Git, retain the paired import metadata by a tested clean-checkout process and generate the GLB before Unity opens. Confirm every material/prefab reference resolves with a new `Library`. [glTFast Editor import](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.19/manual/ImportEditor.html)

## A4. Accept a small set before scaling

Import the asymmetric fixture, bench or gate, glass/alpha fixture, one articulated train car, and one cleared rig with named clips. Required evidence is export/validator/import JSON, bounds and anchor readback, four direction screenshots, a door transition on both sides, motion frames from the browser, and a two-run no-change check. Confirm an edited station can use the same static prefab ID repeatedly. This spike can use a procedurally created rig for clearance.

Use built-in Three.js export and glTFast first. Add pinned glTF Transform for inspection or an explicit optimization pass only after a measured asset budget is exceeded. Test its output against named anchors, skin joints and material regions. Avoid generic flatten/dedup/simplify on authored articulated nodes. Leave Draco, Meshopt and KTX2 off until glTFast and the release build prove the selected extensions and their size/runtime benefit. Use Blender background processing only for a documented asset repair that the native importers cannot express. It should be a pinned script with fixture outputs and no manual clicks. [glTF Transform CLI](https://gltf-transform.dev/cli)

## A5. Bring over catalogue and live geometry by family

1. Start with the pieces in the Zoo playable slice. Export static geometry in batches keyed by catalogue ID. Add placement/camera parity checks for negative coordinates, level offset and four facings. Build a script to diff coverage between shipped catalogue IDs and export/runtime geometry routes.
2. Port floor/wall/ceiling/ramp/roof, then track and road chunks. Compare one-chunk, shared-boundary and dirty-neighbor cases against TS fixture geometry. Preserve cutaway, exploded levels, per-surface finish, material grouping, floor occlusion and camera pick behavior. Regenerate only changed chunks and explicit neighbors. Use capped submesh/material counts and reusable buffers.
3. Add city/station themes, repeated equipment, signs and panels, rail/catenary/bridges, foliage/vehicles and rolling-stock detail. Keep author-edited text, line color, camera visibility and paint separate from geometry recipes. Map dynamic parts to deterministic snapshot fields.
4. Profile a synthetic crowd first and then the cleared full art. Use pooled transient objects and bounded shared GPU buffers. Cover child/adult height, per-agent appearance, occupied hands, stairs, escalators, lifts and seated poses. Compare activity and normal/low LOD frames. Choose batching or pose representation from the Phase 1 measurements. Avoid one Animator or live skeleton per crowd member as the starting architecture.
